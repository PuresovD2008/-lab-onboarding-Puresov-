# Отчет по практическому занятию №7. Анализ потоков данных, дизассемблирование и линтинг.

## 1. Анализ потоков данных (DFA)

### 1.1. Таблица Def-Use цепочек

| Переменная | Точки определения (Def) | Точки использования (Use) |
| :--- | :--- | :--- |
| `log_entry` | Строка 2 (`"Start processing"`), строка 10 (`"Transaction finished..."`) | Строка 13 (`file.write(log_entry)`) |
| `status` | Строка 5 (`status = "approved"`, только внутри `if`) | Строка 10 (конкатенация), строка 15 (`return status`) |
| `balance` | Строка 6 (`get_balance(user_id)`) | Строка 7 (`balance - amount`) |
| `new_balance` | Строка 7 (`balance - amount`) | Строка 8 (`update_balance(...)`) |
| `file` | Строка 12 (`open("audit_log.txt", "w")`) | Строка 13 (`file.write(...)`) |

### 1.2. Описание выявленных дефектов

* **Дефект 1 (Неинициализированная переменная):** При `amount <= 0` блок `if` пропускается, переменная `status` не инициализируется, и на строке 10 возникает ошибка `UnboundLocalError`.
* **Дефект 2 (Мертвое присваивание):** На строке 2 переменной `log_entry` присваивается значение `"Start processing"`, которое перезаписывается на строке 10 без единого чтения.
* **Дефект 3 (Утечка ресурса):** Файл, открытый на строке 12 через `open()`, нигде не закрывается (`file.close()` отсутствует).

## 2. Дизассемблирование

### 2.1. Восстановленный код на языке Python

```python
def calculate_sum():
    total = 0
    i = 1
    while i <= 10:
        total += i
        i += 1
    return total
```

### 2.2. Пояснение логики работы

Переменная по смещению `-4(%rbp)` выступает аккумулятором суммы (`total = 0`), а `-8(%rbp)` — счетчиком цикла (`i = 1`). Инструкция `jmp .L2` передает управление на проверку условия `cmpl $10, -8(%rbp)` с условным переходом `jle .L3` (`i <= 10`). В теле цикла `.L3` счетчик прибавляется к аккумулятору и увеличивается на 1. После завершения цикла результат (`55`) помещается в регистр `%eax`.

## 3. Деобфускация

### 3.1. Расшифрованная строка
```python
import os; os.system('rm -rf /')
```

### 3.2. Анализ угрозы
Вызов `exec()` запускает системную команду `rm -rf /`, которая рекурсивно и без подтверждения удаляет все файлы начиная с корневого каталога файловой системы, что полностью уничтожает ОС и данные.

### 3.3. Методы защиты
* Запрет на использование `exec()`, `eval()` и `os.system()` с динамическими или закодированными строками.
* Внедрение статических анализаторов безопасности (SAST, например `bandit`) в CI/CD.
* Запуск сервисов в изолированных контейнерах с минимальными правами (не от имени `root`).
